> Uses Docling for structure-aware PDF parsing and a production-grade
> hybrid retrieval pipeline (BM25 + MMR + cross-encoder reranking).

## Architecture

```
User Query
    |
    v
[Triage Agent]
  Classifies: policy_lookup / procedure_query /
              eligibility_check / comparison_query / out_of_scope
    |
    +---> [Information Agent]           +---> [Action Agent]
    |       Hybrid retrieval:           |       LangGraph ReAct tools:
    |       - Self-query filter         |       - list_related_policies
    |       - BM25 (keyword)            |       - get_policy_scope
    |       - MMR ChromaDB (semantic)   |       - find_responsible_party
    |       - RRF fusion                |       - suggest_next_steps
    |       - Cross-encoder rerank      |
    |       - Parent-chunk upgrade      |
    |            |                      |
    +---> [Combine Agent] <------------+
              |
              v
         Final Response
         (grounded, cited, professional)
```

**PDF parsing layer:**
```
48 SETU PDFs
    |
    Docling DocumentConverter
    (AI layout analysis: headings, tables, lists preserved as Markdown)
    |
    Parent-child chunking
    (child=256 chars for matching, parent=1024 chars for context)
    |
    ChromaDB (persistent, on-disk)
```

**Retrieval pipeline (per query):**
```
Query
  -> Self-query filter  (detect named policy -> add metadata filter)
  -> Lightweight expand (1 rewrite)
  -> BM25 retrieval     (k=8 keyword matches)
  -> MMR ChromaDB       (k=8 semantic, diversity-aware)
  -> RRF fusion         (merge both lists by rank)
  -> Cross-encoder rerank  (ms-marco-MiniLM, ~50ms, no LLM call)
  -> Top-3 parent chunks
  -> Grounded answer with source citations
```

## Project Structure

```
setu_compliance_rag/
  config/
    llm_config.py          # LLM + embeddings factory (local/openai/anthropic)
  .vscode/
    settings.json          # Points VSCode to the correct Python interpreter
  dataset/                 # One JSON per PDF (committed to git, generated by build_dataset.py)
  chroma_db/               # Generated after ingest.py (gitignored)
  build_dataset.py         # Step 1: Docling PDF -> dataset/*.json  (run once, ever)
  ingest.py                # Step 2: dataset/*.json -> ChromaDB     (fast, repeatable)
  data_preprocessing.py    # Parent-child chunking helper
  triage_agent.py          # Query classifier (6 SETU-specific categories)
  information_agent.py     # Production hybrid retrieval pipeline
  action_agent.py          # LangGraph ReAct tools for policy navigation
  main_agent.py            # LangGraph StateGraph orchestrator
  evaluate.py              # Production metrics: latency, precision, faithfulness
  failure_modes.py         # 5 real production failure modes + fixes
  test_setup.py            # Environment health check
  requirements.txt
  .env.example
```

## Setup

> **Important:** Run all commands from the `setu_compliance_rag/` folder, not from `All Data/`.

```powershell
cd "C:\Users\Keval\Documents\ProjectWork\SETU_Compliance\setu_compliance_rag"
```

### 1. Create and activate local virtual environment

```powershell
python -m venv .venv
.venv\Scripts\activate
```

### 2. Install dependencies

```powershell
pip install -r requirements.txt
```

Key packages:
- `docling` — structure-aware PDF parser (downloads ~500MB AI models on first run)
- `sentence-transformers` — cross-encoder reranking (22MB, runs locally, no API cost)
- `rank_bm25` — BM25 keyword retrieval
- `langgraph` — agent orchestration

### 3. Configure environment

```powershell
copy .env.example .env
```

Edit `.env`:

```dotenv
# Local (Ollama) — zero API cost, all data stays on-device
LLM_PROVIDER=local
LLM_MODEL=gemma3:1b
EMBEDDINGS_PROVIDER=local
EMBEDDINGS_MODEL=nomic

# OR: Anthropic (best quality for policy reasoning)
# LLM_PROVIDER=anthropic
# LLM_MODEL=claude-sonnet-4-6
# ANTHROPIC_API_KEY=sk-ant-...

# OR: OpenAI
# LLM_PROVIDER=openai
# LLM_MODEL=gpt-4o-mini
# OPENAI_API_KEY=sk-...
```

### 4. Verify setup

```powershell
python test_setup.py
```

Expected:
```
[OK] Python version: 3.14.x
[OK] PDF directory exists: 48 PDFs found
[OK] docling importable
[OK] chromadb importable
[OK] Embeddings working: 768 dimensions
[OK] LLM working: yes I am working...
[OK] ChromaDB working: in-memory client OK
```

### 5. Build the JSON dataset (run once, ever)

```powershell
python build_dataset.py
```

This takes 5-20 minutes (Docling parses 48 PDFs and downloads AI models ~500MB on first run).
Output: `dataset/<doc_name>.json` — one file per PDF, committed to git.

### 6. Load dataset into ChromaDB (fast, run any time)

```powershell
python ingest.py
```

Reads from `dataset/*.json` — no Docling, completes in seconds.
Re-run this any time you want to rebuild the vector store.

### 7. Run the chatbot

```powershell
python main_agent.py
```

## Key Design Choices vs Lab-06 Baseline

| Aspect | Lab-06 | This project |
|---|---|---|
| Data source | Inline text strings | 48 PDF files via Docling |
| Chunking | Fixed-size RecursiveCharacterTextSplitter | Parent-child (256/1024) |
| Retrieval | Single similarity_search | BM25 + MMR ChromaDB + RRF |
| Reranking | LLM-based (slow, expensive) | Cross-encoder (local, ~50ms) |
| Query expansion | 3 LLM rewrites | 1 lightweight rewrite |
| Self-query | None | Named-policy metadata filter |
| Agent framework | None | LangGraph StateGraph |
| Evaluation metrics | LLM-as-judge accuracy | Latency + context precision + faithfulness + citation |

## Troubleshooting

**Ollama not running**
```bash
ollama serve
ollama pull gemma3:1b
ollama pull nomic-embed-text
```

**ChromaDB not found**
```
Run 'python ingest.py' first to build the vector store.
```

**Docling first run is slow**
> Normal — it downloads DocLayNet and TableFormer models (~500MB). Cached after first run.

**VSCode shows package hints in requirements.txt**
> The `.vscode/settings.json` points to the correct Python interpreter. Reload VSCode window.

**Unicode errors on Windows**
> All output uses ASCII markers `[OK]`, `[WARN]`, `[INFO]`.
